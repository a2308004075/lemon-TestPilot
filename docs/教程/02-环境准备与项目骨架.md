### 🎯 本章目标

从**一个空文件夹**开始，得到「能跑起来的空壳」：

1. 装好 Node.js 24 并验证；
2. 写出 5 个骨架文件：`package.json`、`index.html`、`vite.config.ts`、`tsconfig.json`、`src/main.tsx`（外加 1 行的 `src/vite-env.d.ts`）；
3. 通过 `npm run check` 类型检查 + 临时 `npx vite` 在浏览器里看到 React 页面（含热更新）；
4. 学会排查 4 类最常见的启动失败。

> 本章结束时你还不会看到 3344 端口——「一个端口跑前后端」是第 3 章 `server.mjs` 的功劳。本章先用 Vite 自己的 5173 端口验证前端骨架。

### 🚧 前置条件

- 一台电脑（Windows / macOS 均可，本章两套命令都给出）；
- 可以联网（安装 Node 和依赖需要）。

## 2.1 安装 Node.js 24

### 安装步骤（Windows）

1. 打开 <https://nodejs.org/>，下载 **LTS 版本**（安装包名字形如 `node-v24.x.x-x64.msi`）；
2. 双击安装，一路默认（安装器会自动把 `node` 加入 PATH）；
3. 安装完成后**新开**一个 PowerShell 窗口，验证：

```powershell
node --version
npm --version
```

预期输出类似：

```text
v24.4.0
10.9.2
```

版本号 ≥ 24 即可（本节写作时 LTS 为 24.x，你安装时可能更高，比如 v25/v26 也没问题）。

### 安装步骤（macOS）

到同一官网下载 `.pkg` 安装包双击即可；或者用 Homebrew：

```bash
brew install node@24
```

验证命令相同：`node --version`。

### 常见问题

| 症状 | 原因与处理 |
| --- | --- |
| `node : 无法将“node”项识别为 cmdlet` | 安装后没有重开终端，或安装时没勾选加入 PATH；重开终端，仍不行就重装 |
| 版本是 v18 / v20 等旧版 | 电脑里装过旧版 Node；到官网下载新版覆盖安装，或先用 `where node`（Windows）/ `which -a node`（macOS）看看有几个 |
| macOS 上 `brew` 里装了多个版本 | `brew link --overwrite node@24` 或直接调整 PATH 优先级 |

> 为什么必须是 24+？第 1 章讲过：数据库层用 Node 内置的 `node:sqlite`，低版本启动就会失败。

## 2.2 初始化项目文件夹

```powershell
mkdir testpilot
cd testpilot
npm init -y
```

`npm init -y` 会生成一个默认的 `package.json`，我们把它的内容**整体替换**成下面这样（逐字段解释见 2.3）：

```json
{
  "name": "testpilot-personal-workbench",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "node server.mjs",
    "build": "tsc --noEmit && vite build",
    "start": "node server.mjs --production",
    "check": "tsc --noEmit",
    "deploy": "node scripts/deploy.mjs"
  },
  "dependencies": {},
  "devDependencies": {},
  "engines": {
    "node": ">=24.0.0"
  }
}
```

> 注意：本章的 `dependencies` / `devDependencies` 先留空——依赖包在 2.8 节一起安装（`npm install xxx` 会自动帮你填上）。最终版本与第 1 章展示的一致。

再顺手建好目录结构：

```powershell
mkdir src, scripts
```

### 建议的 .gitignore

如果你打算用 Git 管理项目，先建一个 `.gitignore`（教学建议，内容可按需增减）：

```text
node_modules/
dist/
data/
logs/
```

四个都要忽略的原因：`node_modules/` 是依赖（可由 lock 文件重装）；`dist/` 是构建产物；`data/` 是你的**本地数据和加密密钥**——绝不进版本库；`logs/` 是运行日志。

## 2.3 package.json 逐字段解释

| 字段 | 值 | 为什么 |
| --- | --- | --- |
| `name` / `version` / `private` | — | 项目标识；`private: true` 防止误发布到 npm |
| `type` | `"module"` | 全项目启用 ES Module（`import/export`）。一旦开启，`require` 就不能用了 |
| `scripts.dev` | `node server.mjs` | 开发模式。注意**不是** `vite` 命令——服务器自己内嵌 Vite（第 3 章） |
| `scripts.build` | `tsc --noEmit && vite build` | 先类型检查（不产出），再打包。顺序很重要：类型不过就不构建 |
| `scripts.start` | `node server.mjs --production` | 生产启动，`--production` 让服务器只服务构建产物 |
| `scripts.check` | `tsc --noEmit` | 单独跑类型检查，改完代码先过这一关 |
| `scripts.deploy` | `node scripts/deploy.mjs` | 一键部署入口（第 10 章） |
| `engines.node` | `>=24.0.0` | 声明运行底线；npm 安装依赖时会提示不满足的环境 |

## 2.4 index.html —— 唯一的 HTML 容器

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="description" content="TestPilot 个人测试智能工作台" />
    <title>TestPilot · 个人测试工作台</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

三个关键点：

1. `<div id="app"></div>`：React 应用唯一的挂载点，**整个界面（十几个页面、弹窗、抽屉）都渲染在这一个 div 里**；
2. `<script type="module" src="/src/main.tsx">`：浏览器直接以模块方式加载 TSX——这是 Vite 在开发态的能力（浏览器本身不认 TSX，Vite 会即时编译）；生产构建时会自动替换为打包后的 JS 引用；
3. 没有引入任何 CSS 文件——样式由 `main.tsx` 里 `import './styles.css'` 引入。这是打包器世界的特点：**入口在 JS，资源都是 JS 的依赖**。

## 2.5 vite.config.ts —— 整个构建配置只有 7 行

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  build: { outDir: 'dist' }
});
```

| 部分 | 作用 |
| --- | --- |
| `import { defineConfig } from 'vite'` | `defineConfig` 本身只是类型辅助函数（让你有自动补全），运行时不做事 |
| `react()` 插件 | ① 让 Vite 认识 JSX/TSX 语法；② 提供 React 组件级热更新（Fast Refresh）——改组件代码时浏览器不刷新、局部更新 |
| `build.outDir: 'dist'` | 构建产物输出目录。其实 Vite 默认就是 `dist`，这里显式写出来是为了和后端静态服务、部署脚本的约定**对齐并可见** |

为什么配置能这么短？因为 Vite 的默认值很合理：入口自动找 `index.html`、开发服务器默认 5173、生产构建自带代码分割。**只写你真正改变了的东西**。

## 2.6 tsconfig.json —— 类型检查的规则书

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "skipLibCheck": true,
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "strict": true,
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "jsx": "react-jsx"
  },
  "include": ["src"],
  "exclude": ["dist", "node_modules"]
}
```

逐项解释（这一节值得慢看，后面写代码时的每个报错都和它有关）：

| 选项 | 含义 | 为什么这样选 |
| --- | --- | --- |
| `target: ES2022` | 编译目标语法级别 | 现代浏览器都支持 ES2022；配合 Vite 打包不需要降级到 ES5 |
| `lib` | 可用的内置类型库 | `ES2022` 给语言特性；`DOM` 给 `document`/`fetch` 等浏览器 API；`DOM.Iterable` 让 DOM 集合可被 `for...of` 遍历 |
| `skipLibCheck: true` | 跳过对 `.d.ts` 声明文件内部的一致检查 | 加速检查（依赖的声明文件往往有些小毛病，检查它们纯属浪费时间） |
| `esModuleInterop` + `allowSyntheticDefaultImports` | 允许 `import React from 'react'` 这种“默认导入 CJS 包”的写法 | 兼容第三方库的模块形态，避免互操作报错 |
| `strict: true` | 开启全部严格检查（含 `strictNullChecks` 等） | 宁可编译期报错，不要运行期 bug——本项目所有代码都在严格模式下编写 |
| `module: ESNext` / `moduleResolution: Bundler` | 按打包器语义解析模块 | 支持 Vite 的解析规则（无扩展名导入、路径别名等） |
| `resolveJsonModule: true` | 允许 `import data from './x.json'` | 备用能力（本项目未用到，但配置上开了） |
| `isolatedModules: true` | 要求每个文件可独立编译 | Vite 用 esbuild 逐文件转译（不跨文件分析类型），此项保证写法与之兼容 |
| `noEmit: true` | **只检查，不产出 JS** | 产出交给 Vite。tsc 和 Vite 各司其职，避免两套产物打架 |
| `jsx: "react-jsx"` | 新版 JSX 转换模式 | 写组件**不需要**手动 `import React`；只有用到 `React.xxx` 类型/API 时才 import |
| `include: ["src"]` | 只检查 src 目录 | 后端 `.mjs`、配置文件不参与 TS 类型检查（它们语法上本来就是合法 JS） |

## 2.7 最小 React 应用

### src/vite-env.d.ts（1 行，别漏）

```ts
/// <reference types="vite/client" />
```

这行三斜线指令让 TS 认识 Vite 注入的客户端类型（如 `import.meta.env`）。文件名叫 `*.d.ts` 表示它是“只为类型服务”的声明文件。

### src/styles.css（先写最小版）

```css
:root { font-family: 'Noto Sans SC', system-ui, sans-serif; color: #1d1f1c; background: #f4f4ef; }
* { box-sizing: border-box; }
body { margin: 0; display: grid; place-items: center; min-height: 100vh; }
```

先让页面居中显示一行字；完整样式体系在第 6 章展开。

### src/main.tsx（最小可运行版）

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import './styles.css';

function App() {
  return <h1>TestPilot 启动成功</h1>;
}

createRoot(document.getElementById('app')!).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

逐行读：

1. `import { StrictMode }`——React 组件；`createRoot` 来自 `react-dom/client`，是 React 18+ 的新入口（旧教程里的 `ReactDOM.render` 已废弃）；
2. `document.getElementById('app')!`——末尾的 `!` 是 TypeScript 非空断言：“我确认这个元素一定存在”（它来自 `index.html`）。如果这里写错 id，运行时会报 `Cannot read properties of null`；
3. `createRoot(...).render(...)`——把组件树渲染进挂载点；
4. `StrictMode`——开发模式下的额外检查器（例如提示不纯的副作用、废弃 API）；生产构建自动移除。

## 2.9 里程碑验证

### 验证 A：类型检查通过

```powershell
npm run check
```

预期输出：**没有任何输出**、退出码 0。TS 的哲学是“没消息就是好消息”。如果报错，会带文件、行列号和错误说明——按提示改。

### 验证 B：前端骨架跑起来（临时用 Vite 自己的端口）

> 注意：此刻 `server.mjs` 还不存在（第 3 章才写），所以不能用 `npm run dev`（它是 `node server.mjs`）。先用 Vite 独立模式验证骨架：

```powershell
npx vite --port 5173
```

预期终端输出（关键行）：

```text
  VITE v8.x.x  ready in 300 ms
  ➜  Local:   http://127.0.0.1:5173/
```

浏览器打开 `http://127.0.0.1:5173/`，应该看到居中的 **“TestPilot 启动成功”**。

### 验证 C：热更新是真的

不要关终端，把 `main.tsx` 里的文字改成「TestPilot 骨架 OK」并保存——浏览器页面**不刷新**（注意看标签页没有转圈）但文字立即变化。这就是 2.5 节 `react()` 插件提供的热更新。

验证完按 `Ctrl+C` 停掉临时 Vite。

### ⚠️ 要点与坑

1. **`"type": "module"` 一开，`require` 就不能用了**。如果从老教程复制了 `const http = require('http')` 会直接报 `require is not defined`，全部换 `import`；
2. **`jsx: "react-jsx"` 下不必再写 `import React from 'react'`**（写了也不报错，但属于噪音）；只有用到 `React.ReactNode` 这类类型时才需要 import；
3. **不要用 `file://` 直接打开 `index.html` 调试**——模块化脚本和 API 请求都需要 HTTP 服务；
4. **`npm init -y` 生成的默认 `name` 带大写或中文时**，npm 可能报错，直接改成全小写短横线格式（如 `testpilot-personal-workbench`）；
5. 安装依赖时如果卡住（网络慢），可以设置国内镜像：`npm config set registry https://registry.npmmirror.com`。

### ✍️ 练习

1. 把页面标题改成你的名字，验证热更新（保存后浏览器自动变化，无需刷新）；
2. 故意制造两类错误，观察反馈：① 在 TS 里把 `createRoot` 拼错，跑 `npm run check` 看类型报错；② 把 `index.html` 里的 `id="app"` 改成 `id="root"`，刷新浏览器看控制台运行时报错——体会「编译期错误」与「运行期错误」的区别。
