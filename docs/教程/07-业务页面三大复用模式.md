### 🧠 设计思路与原理

#### ① 三大复用模式是怎么来的？

13 个页面如果每个都从零写，就是 13 套表格样式、13 套提交逻辑、13 套详情布局。这个项目把页面归纳成三种形状，新页面只要「选形状 + 填内容」：

| 模式 | 状态形状 | 页面骨架 | 代表页面 |
| --- | --- | --- | --- |
| 列表页 | 筛选条件（q / moduleId / priority / page） | filterbar → 表格 → 分页 →（点行）抽屉 | CasesPage、KnowledgePage、ReportsPage |
| 工作区页 | 表单草稿（title / text / moduleId） | smart-panel 输入区 + 右侧反馈栏 → 提交 → 抽屉 | AnalysisPage、CaseEditor、GenerateRegression |
| 详情抽屉 | 一条记录（item） | 徽章行 → DetailGrid → detail-section 若干 → 动作按钮 | DetailDrawer（承载 6 类记录） |

#### ② 为什么详情做成抽屉而不是页面？

因为「查看一条任务详情」有**三个入口**都要用：首页的最近任务、分析页的任务列表、第 8 章 AI 助手刚跑完的结果。做成独立页面就要复制三份详情 UI；做成抽屉，任意位置只要 `setDrawer({type:'task',item})` 即可。整个应用只有**一个** `DetailDrawer` 实例，挂在最外层（第 6 章 App 的第三区域）。

#### ③ 数据流：谁负责请求数据？

- `bootstrap`（模块列表 / 统计数字 / 模型配置）：App 启动拉一次，所有页面共享；
- **列表数据：每个页面自己拉**——自己关心筛选条件和分页；
- 写操作后手动刷新：`load()` 更新自己的列表，`refresh()` 更新 `bootstrap.counts`（首页数字会变）。

没有 Redux、没有 Context——「谁用谁拉、改完刷新」。单用户本地工具的规模下完全够用（第 1 章的决策：不引入状态库）。

#### ④ 为什么能「一个文件平铺几十个函数」？

`function` 声明会**提升**（hoisting）：文件下方定义的 `PanelTitle`、`shortModule`，上方组件直接使用完全没问题（定义在运行时早于渲染调用）。这就是第 6 章敢把「占位 stub 写在 App 后面」、本章敢把「工具函数写在文件末尾」的底气。注意这是 `function` 声明的特权——如果你改用 `const PanelTitle = () => ...`，就会踩「未初始化」错误。

上面这段与真实文件第 76–86 行**逐字一致**。逐块解读：

**① 最近任务只取 5 条**（第 77 行）：

- `API.list('tasks',{pageSize:20})` 请求 20 条，再 `.slice(0,5)` 截 5 条——为什么不直接 `pageSize:5`？因为后端 `pageSize` 有白名单 `[20,50,100]`（第 5 章 5.1），传 5 会被兜到默认值 20。**先用合法参数拿一页，再本地截断**，这是迁就接口约束的小技巧；
- `useEffect(...,[])` 空依赖 = 只在挂载时拉一次。

**② metrics 六卡：混合数据源**（第 78 行）：

```tsx

['待审核', recent.filter(i=>i.reviewStatus==='待审核').length, ...]  // 实时计算
['执行中', 1, ...]                                    // 常量
['阻塞', 1, ...]                                      // 常量
['高风险', recent.filter(i=>i.risk==='P0').length, ...]              // 实时计算
['不可上线', 0, ...]                                  // 常量
```

六个指标里只有「待审核」「高风险」是真数据（从刚拉的 20 条任务里过滤）。

- 真实项目的**诚实欠账**：后端没有「按状态聚合统计」的接口，所以四个数字先写成演示值。好处是演示值集中在**一个数组**里，将来有了统计接口，只需把常量换成接口返回值；
- 每个指标的四元组 `[标签, 数值, 说明, 颜色类]`：颜色类直接映射到 CSS——`warn/yellow/red/blue/dark` 对应 `.metric.warn:before` 等（第 6 章类名族谱第 5 行：左侧 4px 色条）。

**③ hero 横幅与快捷入口**（第 80–82 行）：

- hero 的巨型「T」水印是纯 CSS（`.hero:after`），JSX 里看不到——第 6 章已埋过；
- 快捷入口遍历 `TASK_META` 的六个任务类型生成卡片。**注意 id → page 的映射**：


`regression`、`cases` 与页面 id 同名；只有 `report` 要映射到页面 `reports`（多了个 s）。`as PageKey` 断言是因为 `id` 的类型是 `string`，TS 无法确认它落在 13 个页面 id 的联合类型里。

**④ 数据资产四连**（第 83 行）：数字全部来自 `bootstrap.counts`——这正是第 5 章 bootstrap 接口里 `counts` 字段的消费端。点哪个跳哪个页面，`Asset` 组件（7.16）把「标签 + 数字 + 箭头」封装成一个按钮。

**核心机制：组合任务的父子结构**（第 91 行的 `create`）值得完整走一遍：

1. 勾选**多个**任务类型时，先创建**父任务**：`type:'combination'`、标题自动拼接（`组合任务 · Bug 分析 + 日志分析`）、`result:{progress:0}`——进度字段从一开始就为父任务预留；
2. 循环 `selected`，为每个类型做一次：本地规则分析 `localAnalysis` → POST 创建**子任务**（`parentId: parent?.id` 挂到父任务下，`status:'待审核'`）；
3. 子任务标题用 `guessTitle(text, fallback)` 从输入文本首句提取；
4. 全部完成后 `refresh()`（更新首页统计）→ toast → **打开第一个子任务的抽屉** → 清空输入框。

`missing` 的判断也有意思：`text.trim().length>30 ? [] : 必填项全集`——文本超过 30 字就默认「信息够用」，否则列出所有勾选任务必填项的**并集**（`flatMap` 展开 + `Set` 去重）。这是一个**演示级的启发式**，不是真正的字段识别（第 5 章后端 `missingFields` 同样如此）。

**它为什么没挂载？** 产品的演进：早期「快速创建」是一个独立页面；后来第 8 章的 **AI 测试助手（AssistantPage）**做成了更完整的「一句话发起 + 任务路由」，功能覆盖了 QuickTasks。出于「先不删、观察是否还有人需要」的稳妥策略，代码被留在文件里——这就是**遗留代码（legacy code）**。

**如何识别这类代码？** 三个信号：① 在 App 的分发区搜索组件名无结果；② 全项目搜索只有一个引用（即定义处）；③ 样式类（如 `.task-selector`）仍有 CSS 但界面上找不到。练习 5 会让你把它「复活」，亲眼看看它的界面。

顺手记住这个「父子任务」模式——第 8 章 AI 助手的多路由执行（`sequential_when_matched`）和它讲的是同一件事：**一次输入、多个关联任务、汇总进度**。

这是全章最长的一段 JSX。拆成五块看：

**① 十一个状态变量**（第 100 行）——先分类再理解：

| 类别 | 变量 | 作用 |
| --- | --- | --- |
| 页签 | `tab` | library / new / execution 三个视图切换 |
| 筛选 | `q` `moduleId` `priority` `page` `pageSize` | 查询参数五件套 |
| 数据 | `data` | 服务端返回 `{items,total,pages}`（初始值给好空壳，首屏不报错） |
| 交互 | `selected` | 勾选的用例 id 数组 |
| 交互 | `treeOpen` | 模块树每个节点的展开状态（`Record<string,boolean>`） |

**② 「筛选即查询」闭环**（第 101–102 行）：

```tsx
const load=()=>API.list('cases',{q,module_id:moduleId,priority,page,pageSize}).then(setData);
useEffect(()=>{load()},[q,moduleId,priority,page,pageSize]);
```

五个筛选参数进了依赖数组——任何一个变化，effect 重跑、`load()` 重查。**你不需要手写「点搜索按钮再查询」的逻辑**，React 的依赖追踪充当了查询触发器。这也是为什么搜索框输入会「边打边搜」（依赖 `q` 每次击键都变）。注意参数名 `module_id`——这里用的是**后端字段名**（snake_case），而 state 变量名用 camelCase，API 层不做转换，要自己对应（第 5 章 `listResource` 认的就是 `module_id`）。

顺便发现一个**真实瑕疵**：`q` 和 `moduleId` 的 onChange 里都有 `setPage(1)`（筛选变化回到第一页），但 `priority` 的下拉 onChange 里**漏了**。后果：在第 2 页把优先级筛成 P0，页码不会重置——数据可能「看起来是空的」（其实 P0 都集中在前几页）。这是适合动手修的真 bug，练习 1 交给你。

**③ 模块树（左栏）**：`grouped` 由 `groupModules(bootstrap.modules, data.items)` 现算（第 102 行）：拿「模块表 × 当前页用例」，拼出 `项目 → 模块 → 子模块 → 用例数组` 的三层嵌套对象。**树是数据的投影**：筛选变了，树跟着变（`hint="显示当前筛选数据"`）。

树节点用 `TreeNode` 递归两层，叶子是普通 `button`：

```tsx
<button className="tree-leaf" onClick={()=>setModuleId((items as Row[])[0]?.moduleId)}>
```

点击叶子 = **把这组的第一个用例的 `moduleId` 设为筛选值**。为什么从数据反推而不是直接用子模块名？因为 `groupModules` 只按名字分组，没有存 submodule 的 id；而 `moduleId` 恰好是后端支持的等值过滤字段（第 5 章 5.1 的过滤清单）。**绕了一下，但闭环了**。

「全部收起」按钮的实现有意思（第 105 行）：遍历 grouped，把所有项目的开关设为 `false`——推平成一层的 `closed` 对象后一次性 `setTreeOpen(closed)`。而 `open={treeOpen[project]!==false}` 的语义是「**没记录过就是展开**」（`undefined !== false`）——所以默认全开，只有显式记录过 `false` 的才收起。

**④ 表格与勾选**（第 108 行）：

- 表头复选框 = **全选/全不选**：`checked={data.items.length>0&&selected.length===data.items.length}`（两个条件防「空页全选」假象），onChange 一次 `setSelected(全部 id / [])`；
- 行复选框的 `<td onClick={e=>e.stopPropagation()}>`——**阻止冒泡**！因为行的 onClick 是「打开抽屉」，如果不拦住，点复选框会同时勾选 + 弹抽屉。这是表格里交互嵌套的经典处理；
- 其余列全是「展示翻译」：`shortModule(c.moduleLabel)`、`<Badge value={c.priority}/>`、`date(c.createdAt)`、`v{c.version}`——这些工具函数让 JSX 保持一行一件事；
- 表格外层的 `table-panel` 是第 6 章 CSS 里「padding:0 的表格专用面板」，配 `table-wrap` 提供横向滚动。

**⑤ 导出与批量操作**：

`exportCases(format)` 的三行里藏着一个**范围规则**：

```tsx
const rows=data.items.filter((x:Row)=>!selected.length||selected.includes(x.id))
```

「**没勾选 = 导出当前页全部；勾选了 = 只导勾选的**」。导出对象把嵌套的 `content` 拍平成两列（`步骤` 用「；」连接、`预期` 单值）——**导出格式向表格用户妥协，而不是照搬数据结构**。

bulkbar（勾选后浮现的黑条）五个按钮：两个只弹提示（演示占位），两个**跳页**（`setPage('regression')` / `setPage('reports')`——带到那些页面继续操作），一个「下载 CSV」复用导出函数。

## 7.4 CaseEditor：表单工作区（真实 114 行）

```tsx

```

三个设计点：

**① 单一表单对象 + 柯里化 set**：整个表单是一个 state 对象，`set(k,v)` 生成「设置某个字段」的更新函数——`set('title',e.target.value)` 比 `setForm({...form,title:e.target.value})` 少写一半。注意它用的是函数式更新 `setForm(s=>({...s,[k]:v}))`（不读闭包里的 form），连续输入不会有「丢失击键」问题。

**② 步骤的输入输出变换**：输入框里是**多行文本**（每行一步），提交前 `form.steps.split('\n').filter(Boolean)` 变成**数组**——对应第 4 章 `cases` 表的 `contentJson` 列结构 `{precondition,steps:[...],expected,testData}`。后端正则发现是 `_json` 结尾的列会自动 JSON.stringify（第 4 章 mapRow 的反向），所以前端送对象、库里存文本、读取时再解析回来——**两端都不用手写 JSON 序列化**。`.filter(Boolean)` 过滤空行（用户可能连打回车）。

**③ done 回调的链式刷新**（在 CasesPage 第 109 行传入）：

```tsx
<CaseEditor modules={bootstrap.modules} notify={notify} done={()=>{setTab('library');load();props.refresh()}}/>
```

保存成功后 `done()` = 切回列表页签 + 重查列表（新用例出现）+ 刷新全局统计（首页数字 +1）。**子组件不关心刷新逻辑，只负责在合适的时机回调 `done`**——这是本项目回调式通信的标准写法（没有事件总线、没有状态库）。

**验证点**：新增一条用例（标题/步骤/预期必填），保存后自动回到列表且新用例出现在表格头部附近；刷新页面数据仍在（真的进了 SQLite）。

**① `meta` 一处取数、四处消费**（第 116 行）：

**② `run()` 的分析管线——全章最值得精读的 15 行**：

```
校验（标题 + 文本≥10 字）
  → 先跑本地规则：localAnalysis(taskType,text)，model='本地规则'
  → 在 bootstrap.providers 里找「启用且已配 Key」的厂商

     → AI 调失败：catch 住，toast「已使用本地规则」——本地结果照常用
  → POST /tasks 创建任务（状态'待审核'、input:{text}、result、model）
  → toast → 打开新任务抽屉 → 清空输入 → load()（列表）+ refresh()（统计）
```

三层容错设计值得逐一说：

- **本地规则先行**：`localAnalysis`（7.17 详解）永远先给出一份「保底结果」——AI 不可用时业务不中断；
- **AI 是增强层**：`result={...result,...ai.result}`——AI 返回的同名字段覆盖本地（比如 AI 给了更准的 `summary`），没给的字段保留本地的。**合并而非替换**，保证结果结构完整；
- **降级不抛错**：AI 调用被**内层 try/catch** 单独包住——模型挂了只会 toast 提醒，不阻断任务创建。外层 try/catch 只管真正的失败（连本地任务都建不了）。

`model` 字段像「生产批次号」——同一条任务，一眼看出结论是本地规则算的（'本地规则'）还是哪个模型算的（'deepseek / deepseek-chat'）。这是第 9 章「模型接入」要接力的钩子。

**③ 三个页签对应三种子视图**：

- `new`：工作区（重点）；
- `list`：轻量列表页——复用 `TaskTable`（7.15）+ 搜索框（注意这里 `onChange={setQ}` 直接传函数，SearchBox 内部 `onChange(e.target.value)` 回调）；
- `knowledge`：**按任务类型映射知识分类**（bug→历史 Bug 库、logs→日志规律库、sql→SQL 经验库），复用 `KnowledgeExperience` 卡片列表（7.15）——「已入库经验」直接作为分析时的参考素材。这是「分析 → 审核 → 入库 → 下次分析引用」知识闭环的前半段，后半段在 7.12 抽屉里。

**④ 附件按钮是「预留入口」**：`<label className="button file-button">` 包着隐藏的 `<input type="file">`（CSS `.file-button input{display:none}`），点 label 触发文件选择；onChange 只 toast 文件名——**真实项目尚未做文件解析入库**，但交互入口先立住了。诚实标注比假装完整重要。

**① 进度环：CSS 的 conic-gradient 魔法**（第 123 行的 `progress-ring`）：

```tsx
<div className="progress-ring" style={{'--progress':`${r.progress*3.6}deg`} as React.CSSProperties}>
```

- HTML 里没有画圆的元素——圆环是 CSS `conic-gradient(var(--yellow) var(--progress),#eee 0)` 画的（第 6 章 CSS 第 8 行已埋过）。**JS 只负责把一个自定义属性 `--progress` 传进去**；
- `r.progress` 是百分比（如 67），乘 `3.6` 得角度（`67×3.6=241.2deg`）——因为一整圆是 360°，百分比 → 角度就是乘 3.6；
- `as React.CSSProperties`：TS 不认识 `--progress` 这种 CSS 自定义属性，需要类型断言放行；
- 内圈白圆和百分数由 `:after` + `<strong>` 叠加——**样式与逻辑完全分离**：要改环的颜色/粗细，去 CSS；要改进度，改数据。

**② 「即改即存」的就地突变**（select 的 onChange）：

```tsx
onChange={async e=>{item.status=e.target.value;await API.patch('regressions',r.id,{data:r.data});notify('执行状态已更新');load();refresh()}}
```

三步：① 直接给 `item.status` 赋值——**注意，这是就地修改 React state 里的对象**（`item` 是 `data.items[i].data.items[j]` 的引用）；② 把整个 `data` 对象 PATCH 回去（后端 `??` 并入式更新，第 5 章）；③ `load()` 重新拉取——**用服务端返回的新数据整体替换 state**。

为什么这样能工作？① 的突变虽然违反 React「不可变更新」原则，但立即被 ③ 的整体替换覆盖，中间没有任何渲染发生（都发生在同一个异步回调里）。代价：如果去掉 `load()`，UI 就不会更新（state 引用没变，React 不会重渲染）。**这是个「能跑但脆」的写法**——一旦有人加上乐观更新逻辑就会出 bug。理解它、然后在你自己的代码里用不可变写法（练习 4）。

后端在这里也配合得很默契：PATCH 后服务端根据新的 items 重新计算 `progress`（第 4 章种子阶段提过的 2/3→67%）并返回——**进度不进数据库，每次现算**（第 5 章 5.4⑦）。

**③ 顶部按钮的现实局限**：`exportRegression(data.items[0],notify)` 固定导**第一条**清单——因为 PageIntro 在卡片列表之外，按钮拿不到「当前操作的是哪张卡」。真实局限，注释里第 6 章的「已知粗糙点」又多一个实例。

**④ 复制清单**：`regressionText(r)` 生成 Markdown 勾选清单（含 `- [x]`/`- [ ]`，7.17 详解），`navigator.clipboard` 写入剪贴板。注意：clipboard API 要求**安全上下文**——`127.0.0.1` 算安全（浏览器特例），但如果你把服务部署到局域网 IP（`http://192.168.x.x`）会失败。

**验证点**：种子数据有一条 2/3 的回归清单——把某个 select 从「未执行」改「通过」，进度环和底部统计联动更新；点「复制清单」粘贴到任意 Markdown 编辑器看效果。

**① 双数据源**（第 127 行）：`useEffect` 里同时发起两个请求——报告列表（服务于列表页签）+ 任务全量（`pageSize:100`，服务于来源选择器）。展示型数据（列表）用 `data`，操作型数据（来源）用 `tasks`，两个 state 各司其职。100 是白名单上限（第 5 章），如果任务超过 100 条，来源选择器就看不到后面的——**又一个已知局限**。

**② `generate()` 的数据组装——报告是一份「快照」**（第 128 行）：

```tsx
const chosen=tasks.filter(t=>selected.includes(t.id));
```

一切从「勾选了哪些任务」出发，然后一次性算出六个字段：

| 字段 | 算法 | 设计意图 |
| --- | --- | --- |
| `modules` | 去重后的模块名数组（`[...new Set(...)]`） | 报告要写「覆盖了哪些模块」 |
| `passed` | 已完成任务数 | 通过数代理（没有真实执行结果表） |
| `failed` | P0 任务数 | **风险代理失败**——欠账，但方向保守（宁多报） |
| `blocked` | 阻塞任务数 | 直接数 |
| `sources` | `{type:'task',id}` 数组（**核心**） | 可追溯：这份结论引用了哪些任务 |
| `risks` | P0 任务标题数组 | 风险清单 |

`sources` 是全项目**引用关系机制的入口**：POST /reports 时后端把每个 source 写进 `relations` 表（第 5 章 5.4⑧）——将来「这条任务被哪些报告引用」就靠它。你在第 5 章验证过的「撤销知识被引用会 409」用的就是同一张 relations 表。**引用数据一旦断链，追溯就无从谈起**——这就是为什么宁可多写一行 sources，也不肯省。

**③ 生成后立刻打开抽屉**（`setDrawer({type:'report',item:report})`）——POST 的返回值直接当抽屉数据用，不用重新拉列表。**「创建 → 展示」一步到位**，用户立刻看到成果（含 PDF 下载入口，7.13 详解）。

**④ `projectName:'电商平台'` 硬编码**——单项目时代的遗留。多项目后应该从模块配置推导（练习 3）。

**⑤ source-picker**：整行是一个 `<label>` 包复选框 + 图标 + 标题 + 风险徽章——**点整行都能切换勾选**（label 默认行为），不用精准点那个小复选框。CSS `.source-picker` 限制了最大高度能滚动（来源多时不撑爆页面）。

**验证点**：生成报告前先到「Bug 分析」造两三个任务；回到报告页勾选它们 → 填写标题/版本 → 生成 → 抽屉弹出 → 尝试三个导出按钮（复制 / Markdown / PDF）。

### 7.17.1 本地分析家族

**`localAnalysis`——无 AI 时的「保底智能」**：

- 风险判定就一行：`/生产|资损|重复扣款|数据丢失|安全|全量/.test(text)`——命中高危词就是 P0，否则 P1。**六个词是「经验浓缩」**（生产/资损/重复扣款/数据丢失/安全/全量——这六个词在任何测试团队都代表最高优先级）；
- `common` 五字段：摘要（前 120 字）、风险、缺失字段（少于 40 字就报必填清单）、证据（固定值：用户输入 + 模块配置——**每个结论都标注证据来源**）、建议（从 `map` 取）；
- `map` 给四类任务各配三条**领域化的建议**（bug → 比对变更/追 traceId/覆盖高风险用例；sql → 索引/事务/测试环境验证）——这些建议是写给 QA 看的常识清单，**不是 AI 生成但胜似模板**；
- 兜底：`map[type]||['结合历史风险生成结构化结论','保留来源并进行人工复核']`——未知类型（如 report）用通用建议。

这个函数的定位：第 5 章后端 `missingFields`、第 7 章前端 `Completeness`、第 9 章 AI 分析——**本地规则、字数启发式、大模型**三层看护，最便宜的一层永远兜底。

**`outputSections`——每种任务承诺的输出结构**：用三元表达式选择数组（logs 五段、sql 五段、bug 五段、其他四段）。它驱动的 UI：分析页右侧「输出结构」清单（第 118 行 `{outputSections(taskType).map(...)}`）——**先告诉用户会产出什么，再给分析按钮**，这是好的交互承诺。

**`guessTitle`——文本首句取标题**：`text.split(/[。\n]/)[0].slice(0,35)`——按「句号或换行」切第一句，截 35 字；空文本回退到传入的默认标题（任务类型名）。**正则字符类的 `[。\n]` 同时匹配中文句号和换行**——中文文本的朴素起题法。

### 7.17.3 数据变换家族

**`groupBy`——一行 reduce + `||=`**：

```tsx
items.reduce((a:Row,x:Row)=>((a[x[key]]||=[]).push(x),a),{})
```

`(a[x[key]]||=[]).push(x),a`——逗号表达式：先保证分组键存在（`||=` 不存在则初始化为 `[]`），推入元素，返回累计器。**理解成本高但密度极高的一行**（展开写是 5 行）。输出 `{分组值: [元素...]}`。

**`groupModules`——用例的模块树投影**：拿模块表（全量）× 用例数组，只输出「有用例的」分支（`if(!rows.length)continue`——空模块不出现）。三层嵌套对象：`{项目: {模块: {子模块: [用例...]}}}`。注意 `??=` 保证中间层存在（第 4 章讲过 `||=`、`??=` 的区别）。

**`countTree`——递归计数**：数组返回长度（`2`），对象递归求和（`{a:[1,2],b:{c:[3]}}` → 3）。模块树每个节点右侧的徽章数字就用它（第 107 行 `count={countTree(mods)}`）。**递归终止条件 = 碰到数组**。

### 7.17.4 导出体系：四种格式一个管道

导出的四个格式构成一个「管道」结构：

```
页面按钮
 ├─ CSV ──┐
 ├─ XLSX ─┤→ downloadRows(rows, name, format)
 ├─ JSON ─┘      ├─ xlsx：XLSX 三连(json_to_sheet → book_new/append → writeFile)
                 └─ csv/json：先转文本，再转交 ↓
                downloadText(text, name)  ← 浏览器下载的通用底层
                 
报告专用（不走表格管道）：
 ├─ Markdown → reportMarkdown() → downloadText / clipboard
 └─ PDF      → downloadPdf() → 临时 DOM + jsPDF.html() 渲染
```

**`downloadRows`**（第 193 行）：xlsx 走 SheetJS 原生链路（`json_to_sheet` 把对象数组变工作表、`book_new`+`book_append_sheet` 组装工作簿、`writeFile` 直接触发下载）；csv 和 json **偷懒复用同一套转换**：csv 用 `sheet_to_csv`（先建工作表再导出为 csv 文本——免手写 CSV 转义）、json 直接 `JSON.stringify`。注意 csv/json 最后也是交给 `downloadText` 完成的。

**`downloadText`**（第 194 行）——浏览器下载的「三行魔术」：

```tsx
const a=document.createElement('a');
a.href=URL.createObjectURL(new Blob([text],{type:'text/plain;charset=utf-8'}));
a.download=name;
a.click();
URL.revokeObjectURL(a.href);
```

创建链接 → 把文本包成 Blob → 生成临时 URL → 程序化点击 → **立即回收 URL**（`revokeObjectURL`——不回收会造成内存泄漏，每下载一次泄漏一个 blob）。注意 `charset=utf-8`——没有它中文 CSV 在 Excel 里会乱码（经典坑）。

**`regressionText`**（第 195 行）：把回归清单序列化成 Markdown——`- [x] P0 标题｜状态`（通过项打钩，其他留空）——**粘进会议纪要/群聊可直接勾选使用**。

**`exportRegression`**（第 196 行）：把回归项拍平为七列（优先级/回归项/模块/状态/预期/实际/负责人）→ `downloadRows` 出 XLSX。`moduleFromId` 在这里把 id 翻成中文（硬编码局限因此暴露）；`if(!r)return` 防空（页面顶部按钮可能在没有数据时被点）。

**`reportMarkdown`**（第 197 行）：模板字符串拼一份标准报告——标题、元信息、执行结果、风险清单。Markdown 版本是「给文档系统吃的」，与 `downloadText` 结合（第 154 行「Markdown」按钮）。

**`downloadPdf`**（第 198 行）——全章技术含量最高的导出：

```tsx
// ① 现场造一个离屏 DOM（720px 宽、内联样式、自己拼 HTML 字符串）
// ② 挂到 body 上（jsPDF 要能度量它）
// ③ doc.html() 渲染：四周 24px 边距、autoPaging:'text' 长文本自动分页、width/windowWidth 控制等比缩放
// ④ doc.save() 保存 → page.remove() 清理离屏节点
```

为什么不用 `doc.text()` 逐行写？因为**中文字体**——jsPDF 自带字体不含中文，逐行写要手动注册字体文件（体积巨大）；`html()` 方案让浏览器用它现有的字体渲染 HTML（中文正常显示），jsPDF 只负责「截图式」录入。代价：异步（要 `await`）、依赖离屏 DOM、样式只能是内联的。**理解这个取舍比记住 API 重要**。

### ⚠️ 要点与坑

1. **筛选重置页码的不一致**（三处样本：CasesPage 的 priority 漏了、KnowledgePage 全部漏了）——未修，作为「真实项目也会有的不一致」保留。你自己写新筛选时记住：**筛选变化必须回第一页**；
2. **回归页就地突变的合法性**——`item.status=e.target.value` 能工作只因为紧跟 `load()` 整体替换。去掉 load 就会「改了没反应」；加乐观更新前必须重构为不可变写法；
3. **`Badge` 的 `value||'—'` 对 0 不友好**——与第 6 章 `&&` 左值坑同源：`0` 是 falsy 会显示破折号。目前所有传入值都是字符串所以安全，但如果你将来传数字（如「失败数 0」）要小心；
4. **`e.stopPropagation()` 只在复选框的 `<td>` 上**——如果你给行加新的可交互元素（如行内按钮），同样要拦住行点击，否则「按钮 + 抽屉」一起触发；
5. **PDF 导出依赖 HTML 渲染**——`doc.html()` 方案在字体加载完成前转换会用后备字体；导出前建议页面停留一会儿（嵌入字体不可用）；
6. **导出文件名用 `Date.now()`**——同一秒内连点两次导出会同名覆盖（浏览器会加 (1) 后缀，实际无害）；
7. **报告来源选择器上限 100 条任务**（`pageSize:100` 是白名单上限）——任务超过 100 条时靠前的看不到；同理「数据资产」只显示计数不展示列表；
8. **`useEffect(()=>setForm(p||{}),[selected,p?.updatedAt])` 的巧妙依赖**——把「服务端时间戳」当依赖项是「服务端数据变了就同步表单」的漏子；如果你改成依赖整个 `p` 对象，每次 render 都会重置表单（对象引用每轮都新）；
9. **遗留组件不要随手删**——QuickTasks/WorkflowPage 的存在是「版本可追溯」的体现；删除前要确认：无引用、无样式依赖、后端接口也无对应。本项目选择保留；
10. **中文 CSV 的 `charset=utf-8`**——`downloadText` 的 Blob type 里看似不起眼的这个声明，是 Excel 不乱码的保障。去掉它试试（练习可验证）。
