## 1. 产品简介

TestPilot 是面向个人测试工程师的**本地测试工作台**。所有数据保存在本机 SQLite 数据库中，默认仅本机可访问，无需服务器，也不上传云端。

它把日常测试工作收敛为一条主线：

> **发起任务 → 自动识别与路由 → 按流程执行 → 人工复核 → 沉淀知识 → 生成报告**

### 1.1 能力总览

| 模块 | 一句话说明 |
| --- | --- |
| 工作台首页 | 质量态势指标、快捷入口、数据资产与最近任务 |
| AI 测试助手 | 一句话发起完整测试分析，自动识别主任务与辅助任务并顺序执行 |
| 执行记录 | 保存原始输入、路由、逐步轨迹、证据、缺项与人工复核结论 |
| 用例库 | 按项目/模块/子模块组织用例，支持新增、导出、批量操作 |
| Bug 分析 | 定位现象、证据和回归范围的专项分析 |
| 日志分析 | 还原调用链与异常节点 |
| SQL 分析 | 检查 SQL 正确性、性能与一致性 |
| 回归测试 | 从高风险用例与历史缺陷生成可执行清单，并在线维护执行状态 |
| 测试报告 | 汇总多来源形成统一质量结论，可导出 Markdown / PDF |
| 知识库 | 可编辑、版本化、带引用保护的经验沉淀，供分析任务检索 |
| 工作台编排 | 配置 7 个标准入口的触发词、必填项、知识映射与工作流 |
| 案例验证 | 用固定 walkthrough 回归路由顺序与安全规则 |
| 配置中心 | 三级模块、大模型厂商、输出格式模板与关联规则 |

### 1.2 工作原则（AI 使用边界）

- 证据不足时**明确提示缺什么**，不编造结论；
- 不虚构知识标题或 Bug 编号；
- **AI 不做上线批准**，P0/P1 与 Prompt 测试结果必须人工复核；
- 任务识别、路由、步骤、输入、证据与复核结论全程可追溯。

## 2. 启动与访问

### 2.1 环境要求

- **Node.js 24 LTS 或更高版本**（含 npm），下载：<https://nodejs.org/>
- 操作系统：Windows / macOS
- 浏览器：Edge、Chrome 等现代浏览器

### 2.2 启动方式

将项目完整解压到当前用户可写的文件夹（不要直接在压缩包内运行），然后任选一种方式启动：

| 方式 | 操作 | 适用场景 |
| --- | --- | --- |
| Windows 一键启动 | 双击 `start.bat` | 日常使用 |
| macOS 一键启动 | 双击 `start.command` 或 `启动 TestPilot.command` | 日常使用 |
| 终端通用启动 | 项目目录执行 `npm run deploy` | 任意系统 |

一键启动程序会自动完成：检查环境与端口 → 安装锁定依赖 → 校验并构建 → 启动生产服务 → 打开浏览器。

已安装依赖并构建过之后，也可以直接快速启动，无需再次联网安装：

```bash
npm start          # 直接启动已构建的生产服务
npm run dev        # 开发模式（同样运行在 3344 端口）
```

### 2.3 访问与停止

- 浏览器打开：**<http://127.0.0.1:3344>**
- 服务**保留终端窗口**运行；停止时按 `Ctrl+C` 或直接关闭终端窗口。
- 端口冲突时可设置 `PORT` 环境变量后启动（默认 3344）。

> 提示：数据位于 `data/testpilot.sqlite`。更新代码或重装时请**保留 `data` 文件夹**，否则历史任务、用例、知识会丢失。

## 4. 工作台首页

首页回答一个问题："今天从哪里开始？"

- **六张指标卡**：待补充、待审核、执行中、阻塞、高风险、不可上线，快速了解当前质量态势。
- **创建智能任务**：进入 AI 测试助手发起新分析。
- **快捷入口（6 项）**：生成测试用例、Bug 分析、日志分析、SQL 分析、生成回归清单、生成测试报告，点击直达对应页面。
- **数据资产**：测试用例、任务记录、知识条目、测试报告四类数据的实时统计（来源 SQLite），点击数字区域可跳转到对应模块。
- **最近任务**：列出最近 5 条任务；点击任意一行打开详情抽屉，可查看输入、分析结果并执行审核操作（提交审核 / 审核通过 / 驳回）。

## 5. AI 测试助手（核心功能）

AI 测试助手把"一段材料"变成"一组按顺序执行的分析任务"，是使用频率最高的入口。

### 5.1 发起任务

![02-AI测试助手-发起任务](./手册截图/02-AI测试助手-发起任务.png)

页面由四个区域组成：

1. **可选任务入口**：7 个标准入口（测试用例生成、Bug 分析、日志排查、SQL 分析、回归清单、测试报告、Prompt 测试）。
   - 不勾选任何入口：交给系统自动识别主任务与辅助任务；
   - 勾选指定入口：系统同时执行你指定的任务。
2. **智能输入**：
   - 选择"项目 / 模块 / 子模块"（下拉中只显示启用状态的模块）；
   - 在文本框中粘贴问题、需求或发布材料（支持整段材料，详细字段可在识别后逐项补充）。
   - 也可以点击右上角 **载入支付异常示例** 快速体验完整流程。
3. **附件说明**：附件入口已预留，首版请将关键信息粘贴为文本；敏感日志请**脱敏后**再粘贴。
4. **两个操作按钮**：
   - **识别任务与缺项**：只做预检，不执行分析；
   - **按流程执行**：直接按路由顺序执行完整分析。

### 5.2 识别与预检

![03-AI测试助手-识别与预检](./手册截图/03-AI测试助手-识别与预检.png)

点击 **识别任务与缺项** 后，右侧"执行前检查"面板会解释系统为什么这样匹配：

- **路由列表**：展示命中的任务入口、角色（主任务/辅助任务）以及**信息完整度百分比**；
- **缺少必要信息**：明确列出缺什么（例如"时间范围、SQL 文本"），不会猜测根因；此时可以继续生成待补充记录，补齐材料后重新执行；
- **必要信息检查通过**：全部满足时显示绿色提示，可进入执行。

> 规则：**主任务只保留一个**，其他命中项作为辅助任务依次执行。

### 5.3 按流程执行

![04-AI测试助手-执行结果](./手册截图/04-AI测试助手-执行结果.png)

点击 **按流程执行** 后，系统按固定顺序完成全部路由，随后在页面下方生成**执行结果卡片**：

- 卡片头部：执行 ID（如 `run_xxxxxxxx`）、标题（取自输入材料）、路由数与步骤数、风险等级、状态（待复核/已完成）；
- **路由页签**：区分"主任务"和"辅助任务"，例如：主任务 Bug 分析 → 辅助任务 日志排查 → 辅助任务 SQL 分析 → 辅助任务 回归清单；
- **分块结构化输出**：每个路由一个输出区块，包含引用范围（来自哪些知识库分类）与完整 JSON 结果；
- **人工复核栏**：
  - **确认通过**：确认任务识别、证据、风险与结构化输出无误；
  - **驳回补充**：材料不足或结论有误时驳回，任务回到"待补充"。

页面底部固定显示**全局安全规则**（不编造事实、证据不足时明确提示、不虚构知识标题或 Bug 编号、AI 不做上线批准、P0/P1 与 Prompt 测试结果人工复核）。

### 5.4 后续去向

- 每次执行都会写入**执行记录**（第 6 章），包含逐步执行轨迹；
- 复核通过的任务可在详情抽屉中 **申请入知识库**，沉淀为可被后续分析引用的知识（进入"待审核"状态，需在知识库中审核发布）。

## 6. 执行记录

执行记录回答："这次分析到底执行了什么、结论是什么、谁复核过？"

### 6.1 列表与筛选

![05-执行记录-列表](./手册截图/05-执行记录-列表.png)

- **搜索**：按标题或原始输入检索；
- **状态筛选**：全部状态 / 待补充 / 待复核 / 已完成；
- **表格列**：执行记录（标题 + ID）、主任务、路由数、风险、状态、缺项数、复核状态、更新时间；
- 点击 **刷新** 可获取最新数据；点击任意一行打开详情。

### 6.2 执行详情

![06-执行记录-详情](./手册截图/06-执行记录-详情.png)

详情抽屉（RUN DETAIL）包含两部分：

1. **执行结果**：与 AI 助手页一致的结果卡片，包含每个路由的 JSON 输出和人工复核按钮（可在此直接复核）；
2. **逐步执行轨迹**：按顺序列出每个步骤的执行路由、完成时间与状态，完整还原执行链路。

## 7. 工作台编排

工作台编排用于维护 7 个标准入口的"运行配置"，是自定义任务行为的场所。

![07-工作台编排](./手册截图/07-工作台编排.png)

### 7.1 编辑入口

左侧列出 7 个标准入口（含当前版本号，如 `bug_analysis · v1`），点击任意入口进入编辑。

### 7.2 可编辑的四类配置

| 配置项 | 说明（每行一项） |
| --- | --- |
| 触发词 | 命中该入口的关键词 |
| 必填信息 | 执行前必须提供的信息，缺失时提示补充 |
| 知识库引用映射 | 该入口检索哪些知识库分类 |
| 工作流步骤 | 严格按顺序执行的步骤清单 |

### 7.3 发布规则

- 点击 **保存并发布新版本** 后版本号自动递增（如 v1 → v2）；
- **知识库事实不复制到工作台**，工作台只维护入口、触发词、表单、流程、引用映射与输出规则；
- 历史执行记录保留当时快照；
- 删除工作流步骤前请确认不会破坏输出结构。

## 8. 案例验证

案例验证用于在**发布工作台资产前**做回归：用固定 walkthrough（完整材料）验证路由顺序与安全规则是否符合预期。

![08-案例验证](./手册截图/08-案例验证.png)

每个验证案例卡片包含：

- **完整材料**：固定的输入文本（walkthrough）；
- **预期检查**：预期命中的路由清单与必须满足的规则；
- **运行验证案例**：点击开始验证。

运行后：

- 弹出提示"验证通过：路由与规则符合预期"或"验证失败：请检查触发词与路由顺序"；
- 卡片底部显示 **最近验证时间与实际路由顺序**（例如：`bug_analysis → log_triage → sql_analysis → regression_list`），并更新状态徽标。

## 10. Bug / 日志 / SQL 三类专项分析

三个分析页结构完全一致，区别只在任务模板与输出结构。以下以 Bug 分析为例，日志与 SQL 分析操作方式相同。

![12-Bug分析](./手册截图/12-Bug分析.png)

![13-日志分析](./手册截图/13-日志分析.png)

![14-SQL分析](./手册截图/14-SQL分析.png)

### 10.1 新建分析

页面分三个页签：**新建分析 / 任务列表 / 已入库经验**。

在"新建分析"中：

1. 填写 **任务标题**（例如"支付成功订单未同步"）；
2. 选择模块与风险等级（P0/P1/P2）；
3. 粘贴 **问题上下文**（Bug 现象、复现步骤、日志、SQL 等，输入框占位符会提示建议内容）；
4. 右侧实时显示 **输入完整度**（评分 + 必填信息检查清单）与 **输出结构预览**（每类任务的结构不同）；
5. 点击 **开始分析**。

> 模型说明：系统优先调用"已启用且已配置 Key"的大模型；若未配置或调用失败，会自动回退为**本地规则**分析，并在提示中明确说明（"模型暂不可用，已使用本地规则"）。回退不影响流程，但建议在配置中心补齐模型配置以获得更高质量的输出。

分析完成后自动打开任务详情抽屉，可查看输入信息与结构化分析结果，并执行审核动作：

- **提交审核** → **审核通过 / 驳回**；
- 审核通过后可点击 **申请入知识库**，生成一条待审核知识。

## 17. 常见问题（FAQ）

**Q1：提示 3344 端口被占用怎么办？**  
关闭已在运行的原服务，或设置 `PORT` 环境变量后重新启动（例如 `set PORT=3355`）。

**Q2：分析时提示"模型暂不可用，已使用本地规则"？**  
说明当前没有可用的大模型配置。到 **配置中心 → 大模型** 检查：厂商是否启用、API Key 是否已配置、Base URL 与模型名是否正确，然后点击"测试连接"验证。回退本地规则不影响流程，补齐配置后重新分析即可。

**Q3：任务状态"待补充"是什么意思？**  
表示材料缺少必要信息（如时间范围、SQL 文本）。按提示补齐材料后重新执行，或直接在详情中继续流转。

**Q4：撤销知识时被阻止？**  
该知识已被下游任务引用（引用保护）。详情中会列出具体引用来源，需先处理引用关系后再撤销。

**Q5：如何把分析结论沉淀为知识？**  
在任务详情中点击"申请入知识库"生成待审核知识，然后到 **知识库** 中审核发布。

**Q6：换电脑后模型 Key 失效？**  
API Key 使用本机加密（DPAPI/钥匙串），换机后需在配置中心重新输入保存。

**Q7：页面数据与手册截图不一致？**  
截图采集于真实环境中的某次运行，演示数据（任务、用例、报告）会随后续操作变化，属正常现象。
